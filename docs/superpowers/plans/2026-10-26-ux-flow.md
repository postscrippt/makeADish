# UX and Flow Revision Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fewer choices before menus, no servings, no Ask page, and a glanceable วิธีทำ timeline with safe swap suggestions.

**Architecture:** Two small pure modules (step parser, swap filter) carry the logic and the unit tests. Everything else is UI changes inside the existing pages and components, plus one new mock function. Data shapes in `types/api.ts` stay the same; `servings` is just no longer read.

**Tech Stack:** Next 16 (App Router, `cacheComponents`), React client components, Tailwind v4 tokens from `app/globals.css`, `node --test` for unit tests.

**Spec:** `docs/superpowers/specs/2026-10-26-ux-flow-design.md`

## Global Constraints

- Branch `a/ux-flow`. Stay in `app/`, `components/`, `mocks/`, `design/`, `docs/`. Do not edit `types/api.ts`, `lib/`, `data/`.
- Do not change the shape of anything in `types/api.ts`. Where a type still requires `servings`, pass a fixed value with the comment `// servings unused; removal pending Person B (types/api.ts)`.
- Allergy filtering is hard and done in code. An option or recipe with `allergens: null` is never shown.
- Use only the `DESIGN.md` tokens (`brand`, `brand-deep`, `ink`, `muted`, `edge`, `mist`, `butter`, `butter-soft`, red for allergies and errors, amber for missing items). No emoji as icons, except the existing ⏱ ★ ♥ 🌶 glyphs. Icons are stroked line SVGs: stroke 2, round caps and joins.
- Touch targets are at least 44px, primary buttons at least 48px, and the timeline's bottom button at least 56px.
- Everything must work on mock data with no keys. Check every page at 375px.
- Unit tests live in `app/**/*.test.ts` and run with `npm test` (Node 22 type stripping). Files under test use relative imports or `import type` only, never `@/` value imports.
- Thai copy is exactly as written in the spec and this plan.

## Review Focus

1. **A swap option with unknown allergens** (`allergens: null`) must be hidden, never shown as safe. Tested in Task 2.
2. **A step with no known verb** must still render, with a generic icon, verb "ขั้นที่ N" and the full sentence as detail. Tested in Task 1.
3. **A running timer** must stop cleanly when the user jumps to another step or leaves the page, with no stale countdown or interval. Checked by hand in Task 3, step 4.
4. **A food-type filter that empties the current tab** must show a message and a "ดูทั้งหมด" button that resets to ทั้งหมด. It must never show a bare empty list. Checked by hand in Task 6.
5. **A scan that found nothing** must open the add-ingredient search already focused, with "หาเมนู" disabled. Checked by hand in Task 5.

### Task 1: Step parser

**Files:**
- Create: `app/recipe/steps.ts`
- Test: `app/recipe/steps.test.ts`

**Interfaces:**
- Produces:
  ```ts
  export type StepIcon = "whisk" | "pan" | "pot" | "steam" | "knife" | "mortar" | "add" | "season" | "plate" | "generic";
  export type Heat = 1 | 2 | 3;
  export type ParsedStep = { verb: string; detail: string; icon: StepIcon; heat: Heat | null; minutes: number | null };
  export function parseStep(text: string, index: number): ParsedStep;
  ```

**Rules:**
- **Verb:** the first entry in `VERBS` that `text` starts with. Order the table so longer keywords come first. `detail` is the rest of the text, trimmed. If the rest is empty, `detail` is `""`.
- **No match:** `verb = "ขั้นที่ " + (index + 1)`, `detail = text`, `icon = "generic"`.
- **Heat:** ไฟอ่อน → 1, ไฟกลาง → 2, ไฟแรง or ร้อนจัด → 3, otherwise `null`. Search the whole text.
- **Minutes:** the first `/(\d+)\s*นาที/` in the whole text, otherwise `null`.
- **`VERBS` table** (keyword → icon), longest first:
  - ปรุงรส, ปรุง, หมัก → season
  - ปิดไฟ, ต้ม, เคี่ยว, ลวก → pot
  - ตี, ผสม, คลุก, คน, ตอก, ยี → whisk
  - ผัด, ทอด, เจียว, ตั้ง → pan
  - นึ่ง → steam
  - หั่น, ซอย, สับ → knife
  - โขลก → mortar
  - ใส่, เท, เติม, ราด, โรย → add
  - ตัก, เสิร์ฟ → plate

### Task 2: Allergy-safe swaps

**Files:**
- Create: `app/recipe/swaps.ts` (pure filter), `mocks/substitutes.ts` (table)
- Modify: `mocks/api.ts` (add `getSubstitutes`)
- Test: `app/recipe/swaps.test.ts`

**Interfaces:**
- Produces:
  ```ts
  // app/recipe/swaps.ts
  export type SwapOption = { label: string; ingredientIds: string[]; allergens: string[] | null };
  export type SwapResult = { kind: "none" } | { kind: "unsafe" } | { kind: "ok"; options: SwapOption[] };
  export function safeSwaps(options: SwapOption[] | undefined, allergies: string[]): SwapResult;
  // mocks/substitutes.ts
  export const substitutes: Record<string, SwapOption[]>;
  // mocks/api.ts
  export async function getSubstitutes(ingredientId: string, allergies: string[]): Promise<SwapResult>;
  ```

**Rules for `safeSwaps`:**
- `undefined` or an empty list → `none`.
- Otherwise, drop any option whose `allergens` is `null` or overlaps `allergies`.
- If nothing is left → `unsafe`. Otherwise → `ok`.

- [ ] **Step 1: Write the failing test**

const unknown = { label: "ผงปรุงรส", ingredientIds: ["seasoning"], allergens: null };
const salt = { label: "เกลือ", ingredientIds: ["salt"], allergens: [] };

test("safeSwaps", () => {
  assert.deepEqual(safeSwaps(undefined, []), { kind: "none" });
  assert.deepEqual(safeSwaps([], []), { kind: "none" });
  assert.deepEqual(safeSwaps([soy, salt], []), { kind: "ok", options: [soy, salt] });

### Task 3: วิธีทำ timeline component

**Files:**
- Create: `components/StepsTimeline.tsx` (client), `components/StepIcon.tsx`

**Interfaces:**
- Consumes: `parseStep`, `ParsedStep`, `StepIcon` and `Heat` from Task 1.
- Produces:
  ```ts
  // components/StepsTimeline.tsx
  export default function StepsTimeline(props: { steps: string[]; onFinish: () => void }): JSX.Element;
  // components/StepIcon.tsx
  export default function StepIcon(props: { icon: StepIcon; className?: string }): JSX.Element;
  ```

**Behavior** (spec section 5; mockup option B1):
- State: `current` (index, starts at 0) and `done` (a `Set<number>`).
- **Header row:** "วิธีทำ" on the left, "{done.size} จาก {steps.length} เสร็จแล้ว" on the right.
- **The line:** an `<ol>` with a 3px `edge` vertical line behind 48px circles.
  - Done step: a `brand` circle with a white check, then the verb and detail in `muted`.
  - Upcoming step: a white circle with an `edge` ring, then the verb in `muted`.
  - Each row is a `<button>` that sets `current`. Use `aria-current="step"` on the current one.
- **Current card:** `rounded-3xl bg-white shadow-card`, containing:
  - a `bg-butter-soft rounded-2xl` art area about 110px tall with a 72px `StepIcon`
  - the verb, `text-[26px] font-bold`
  - the detail, `text-muted`
  - pills
- **Heat pill:** `bg-mist`. Show 3 flame SVGs using path `M12 3c3 4 6 6 6 11a6 6 0 0 1-12 0c0-3 2-5 3-7 1 2 3 2 3-4z`. The first `heat` flames are at full opacity, the rest at `opacity-25`. Label: ไฟอ่อน / ไฟกลาง / ไฟแรง. Mark the flames `aria-hidden`; the label carries the meaning.
- **Time pill:** a `bg-butter` button.
  - Idle: "⏱ {m} นาที · เริ่ม".
  - Running: "⏱ mm:ss" counting down. Tapping pauses it, and the label shows "· ต่อ" (continue).
  - At 0: "ครบเวลาแล้ว", plus `navigator.vibrate?.(400)`.
  - Use one `setInterval`, cleared on unmount and whenever `current` changes. The timer resets on step change.
  - Add `aria-live="polite"` only for the "ครบเวลาแล้ว" text.
- **Sticky bottom button:** `btn-primary min-h-14 w-full text-lg`.
  - On any step but the last: "ขั้นต่อไป" (next step). It adds `current` to `done` and moves `current` on by 1.
  - On the last step: "เสร็จแล้ว ให้คะแนนเมนูนี้" (done, rate this dish). It marks it done and calls `onFinish()`.
- After `current` changes, call `scrollIntoView({ block: "center", behavior: "smooth" })` on the current card.
- **Wake lock:** inside the component, in a `useEffect`:
  - call `navigator.wakeLock?.request("screen")`
  - request it again on `visibilitychange` when the page becomes visible
  - release it on unmount
  - catch and ignore every error
- **`StepIcon`:** one 24×24 stroked path per `StepIcon` value. Reuse the mockup paths for steam, whisk and pan. `generic` is a simple chef-hat or circle-dot. All icons are `aria-hidden`.
